# Sopt 6주차 - Domain

## ✨ Domain

> 작업해야할 범위
>
- 시스템의 가장 중요한 비지니스 가치를 제공하는 핵심 도메인과 핵심 도메인을 지원하기 위해 필요한 서브 도메인으로 나뉜다.
- 모놀리틱 구조는 모든 기능이 하나의 코드베이스와 애플리케이션에 통합되어 있다. 단일 배포 단위로 구성되어 있어, 코드 변경이 전체 애플리케이션에 영향을 미친다. 초기 개발과 배포가 간단하고, 한 곳에서 모든 기능을 관리하기 때문에 설정 및 디버깅이 용이하지만 규모가 커질수록 복잡도가 증가한다. 또한, 유지보수와 확장이 어렵고 특정 기능 업데이트할 때 전체 애플리케이션을 다시 배포해야하는 단점이 있다. 그리고 도메인 로직과 기술적인 구현이 섞여서 도메인에 대한 명확한 경계가 없어질 수 있다.
- 도메인 중심 설계는 각 도메인을 독립적으로 관리하고 개발하는 것으로, 각 도메인을 별도의 서비스로 분리하여 개발한다. 비지니스 도메인에 따라 시스템이 구성되며 각 도메인이 독립적으로 배포되고 확장될 수 있다. 각 서비스는 독립적인 데이터베이스를 가질 수 있다.

  → 비지니스 로직과 기술 구현의 경계를 명확히 하고 각 도메인을 독립적으로 관리한다.

- 모놀리틱 = 하나의 커다란 서랍장에 모든 물건을 넣어 관리
- 도메인 = 각 물건을 기능별로 나누어 별도의 상자에 넣어 관

## ✨ 1안 vs 2안

> 객체 지향적 vs 식별자
>

```java
// 객체 지향적 (1안)
// 객체 지향적이고, DB에 직접연동함. Domain Entity 방식
// 
class Order {
		// 주문 식별자
		private OrderNo number;
		
		// 주문자
		@OneToOne
		private Orderer orderer;
		
		// 배송 정보
		@OneToOne
		private Shipping shipping;
	}
	
// 식별자(2안)
// JPA를 간접적으로 사용
// 직접 조인하고, 쿼리문 MYbatis 등을 직접 사용한다.
// 식별자만 가지고 처리하는 로직과 코드가 세분화되었다.
class Order {
		// 주문 식별자
		private OrderNo number;
		
		// 주문자 식별자
		private long ordererId;
		
		// 배송 정보 식별자
		private long shippingId;
	}
```

- 1안 [객체 지향적]
    - Order 클래스는 도메인 로직 중심으로 설계되어 객체 지향적 패턴을 따른다.
    - 객체 간의 관계를 명확히 표현하며 코드에서 비지니스 로직을 수행할 때 객체로 직접 조작한다.
    - JPA의 강점을 활용한다. 단, N+1문제나 테스트에 어려움이 있다.
- 2안 [식별자 중심]
    - 식별자를 통해 데이터베이스에서 직접 쿼리를 수행하거나 별도의 서비으세어 로직을 처리한다.
    - 직접 SQL쿼리를 작성하므로 데이터베이스 성능 최적화를 세밀하게 제어 가능하다.
    - 관계를 관리하는 로직이 서비스 계층이나 다른 컴포넌트로 분산될 가능성이 높다.

## ✨ 페이지네이션

> offset vs cursor
>
1. OFFSET

   : 이전 페이지로 돌아가기와 같은 기능이 중요할 때, 크기가 작은 데이터일 때

    - SQL에서 데이터 조회 시 특정 위치부터 데이터를 가져오는 방식이다.
        - LIMIT = 가져올 데이터의 개수
        - OFFSET = 건너뛸 데이터의 개수

    ```sql
    SELECT * FROM orders ORDER BY id LIMIT 10 OFFSET 20;
    ```

    - 전체 데이터 중 시작 위치에서 데이터를 건너뛴 후 LIMIT 만큼의 데이터를 반환한다.
    - 클라이언트는 페이지 번호를 기반으로 OFFSET 값을 계산한다.
    - 구현이 단순하지만, OFFSET값이 커지면 성능이 저하된다. 그 이유는 DB는 건너뛸 데이터도 모두 읽어야하기 때문이다. 그리고 항상 정렬된 상태에서 작동하므로 정렬 컬럼이 성능 병목이 될 수 있다.
2. CURSOR

   : 대규모 데이터에서 성능이 중요할 때, 일관성이 중요할 때, 무한 스크롤.

    - 특정 지점 이후의 데이터를 가져오는 방식이다. 일반적으로 마지막으로 조회된 데이터의 식별자(ID)를 커서로 사용한다.

    ```sql
    SELECT * FROM orders WHERE id > 100 ORDER BY id LIMIT 10;
    ```

    - 클라이언트는 이전 요청에서 받은 마지막 데이터의 식별자를 저장하고 다음 페이지를 요청할 때 이 값을 기반으로 이후 데이터를 조회한다.
    - 특정 지점 이후의 데이터만 검색하므로 OFFSET에 비해 성능이 좋다. 하지만 커서를 기준으로 동작하므로 데이터 정렬 기준이 변경되면 이전 커서는 사용할 수 없다.

## ✨ 예외처리

> 책임을 던진다(책임을 전파한다) vs 책임을 해결한다(로직을 만들어서 다른 메서드가 모르도록)
>
1. 책임을 던진다(책임을 전파한다)
    - 메서드에서 예외가 발생했을 때, 이를 자신이 처리하지 않고 호출한 상위 메서드로 예외를 넘겨누는 방식이다. throws 키워드를 사용하여 메서드 선언부에 예외를 명시한다.
2. 책임을 해결한다(로직을 만들어서 다른 메서드가 모르도록)
    - 메서드에서 발생한 예외를 스스로 처리하여 다른 메서드가 예외를 인지하지 않도록 숨기는 방식으로 try-catch 블록을 사용하여 처리한다.

- Checked Exception
    - RuntimeException클래스를 상속받지 않 예외로 컴파일 시점에 반드시 처리해야한 예외이다.
- Unchecked Exception
    - RuntimeException 클래스를 상속받는 예외로 컴파일 시점에 강제적으로 처리하지 않아도 되는 예외이다. 실행시에 발생할 수 있는 문제를 나타낸다.
